- Pure TypeScript geometry converts normalized x/y to prepared-image pixels before any distance/angle. Five dimensionless ratios use named documented endpoint selections; rigid image-plane rotation and uniform scale preserve them. No square-image assumption or physical units.
- Optional apparent 2D lower-jaw contour chord angle at 172 using 132/152, explicitly nonclinical. Withheld for unknown/obstructed visibility, invalid or nearly collinear chords and unsuitable quality. No gonial/bone measurement claim.
- Each measurement retains explanation, formula, method version, source references, exact landmark IDs, pixel endpoints, chord lengths, units, availability and reasons. UI rounds ratios to two decimals, angle to whole degrees; stored calculations retain full precision. Inspection highlights the actual selected spans and endpoints.
- Visibility starts unassessed. Visitors can report obstructed regions; dependent values become unavailable. Shape and angle require user visibility review; obstruction assessment is not claimed to be automatic or reliable. No ideal targets, confidence percentages or appearance scores.
- Configurable, versioned provisional rules explain oval, round, square, oblong, heart, diamond and triangular suggestions. Overlap produces mixed; no fit produces uncertain. Missing/unsuitable data produces an unavailable/retake result. Rules are unvalidated styling heuristics, not model predictions.
- Report includes capture quality, visibility review, measurements, styling interpretation, original prepared photo / actual landmark / annotated outline toggles, endpoint inspection, methods and limits.
- Lazy 2.29 kB mesh renderer uses actual xyz with x-width/y-height/z-width scaling, centering and one uniform scale. Official tessellation connections, no template vertices or invented hidden surfaces. Pointer/keyboard rotation and reset view; explicit relative-depth approximation label. A mesh error preserves the 2D report. No extra renderer dependency or WebGL requirement.
- Complete report lives in shared FaceAnalysis, with optional additive trace/visibility/rule fields. App retains it in browser memory across navigation. Visibility/view edits do not rerun detection. New input, clear/reset, retake or reload invalidate it; photo IDs/generation checks prevent stale results. Leaving capture stops its camera/worker while retaining only the in-memory current session.
- Added GEOMETRY_METHODS.md, geometry/topology/shape tests and Apache provenance for official topology/index reference. The canonical OBJ is a test-only reference and never supplies visitor measurements.

## Phase 3 limitations and next phase

- Contour selections, capture thresholds and shape rules are provisional, uncalibrated application choices. Canonical topology/index verification does not establish anatomical validity. User visibility confirmation can be wrong; automatic occlusion detection is unavailable.
- Single-view perspective, distance, pose, expression, facial hair, filters and lighting affect measurements. Upper/cheek spans estimate visible model contours, not hidden hairline or cheekbones. Model z is relative; no measured physical depth, hidden-surface reconstruction, medical scan or physical millimetres.
- Physical camera hardware and Safari/Firefox/iOS/Android were not exercised in Phase 3. Phase 2 controlled-camera tests are recorded below; no new physical-camera success is claimed. Retained worker/CPU limitations still apply.
- Mesh controls were checked in Chromium; a failure to load the lazy renderer preserves 2D. No full GPU/device, screen-reader or touch-hardware compatibility claim.
- Phase 4 was the next scope at this earlier checkpoint; it is now implemented above. Export/integration/deployment preparation remains Phase 5.

## Limits and remaining checks

- Physical laptop/mobile camera hardware, real denied/busy/disconnected device behavior, Safari, Firefox and physical iOS/Android were not tested. Embedded permission restrictions are handled and documented; upload works independently.
- The CPU delegate may still require browser WebGL support for image handling. Unsupported worker/OffscreenCanvas/ImageBitmap or failed runtime initialization yields an honest error; there is no claimed fallback outside the worker.
- Quality thresholds are uncalibrated application heuristics. No universal blur/pose/framing detection or skin-tone fairness calibration is claimed. See QUALITY_CHECKS.md.
- PNG/WebP EXIF parsing is implemented; all-eight-orientation colored-corner tests exercised JPEG. Broader real-device format/EXIF coverage remains useful.
- No photo/report persistence or export. Public static model/runtime files may be cached by the browser; sensitive files/results are not placed in browser storage by app code. Browser garbage-collection timing is outside app control.
- Developer-only browser harnesses and camera/failure-injection fixtures are not imported by the production application. No test portrait pixels or landmark dumps are included in the deliverable source package.
- Local QA servers are temporary; restart with npm run dev or npm run preview. No deployment was performed.
